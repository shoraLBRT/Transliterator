# Transliterator

[English version](README.md)

**Попробовать в браузере:** https://shoralbrt.github.io/Transliterator/ — конвейер
считает прямо на странице (Blazor WebAssembly), текст никуда не отправляется.

**Transliterator** — инструмент для транслитерации огласованного арабского текста
в расширенную русскую кириллицу с применением правил таджвида.

Транслитерация здесь не побуквенная замена. Текст проходит конвейер из одиннадцати
стадий: орфография нормализуется, разбирается в поток фонологических сегментов,
над сегментами работают правила таджвида, и только последняя стадия переводит
результат в графемы по профилю. Обратный порядок невозможен: к моменту побуквенной
замены сукун, шадда, тип хамзы и границы слов уже потеряны, а именно они и нужны
таджвиду.

> Что из правил сделано, а что нет, — в [docs/ROADMAP.md](docs/ROADMAP.md).
> Это единственный источник правды о состоянии конвейера; при расхождении
> с любым другим текстом, включая этот файл, прав ROADMAP.

---

## Особенности

* Транслитерация огласованного арабского текста в расширенную русскую кириллицу —
  или в латиницу с академической диакритикой, тем же конвейером.
* Все одиннадцать стадий конвейера реализованы — от нормализации орфографии
  до кальканя (см. таблицу ниже).
* Правила работают с потоком сегментов, а не с готовой кириллицей: ни одной
  кириллической графемы в коде правил нет — все они берутся из профиля.
* **Профили транслитерации** — JSON-файлы. Два входят в ядро, свои можно
  создавать и править в браузере.
* **Веб-версия**: ввод с пересчётом на лету, готовые суры, правила профиля
  таблицей и редактор профилей — статическая страница без сервера.
* **CLI** с выбором профиля вторым аргументом.
* Тесты на xUnit прогоняют через конвейер весь корпус примеров; сборка и тесты
  идут на каждый pull request.

## Пример работы

**Входной текст (Аль-Фатиха 1–4, арабский с огласовками):**

<!-- readme-example:fatiha-input -->
```
بِسْمِ ٱللَّهِ ٱلرَّحْمَٰنِ ٱلرَّحِيمِ ١ ٱلْحَمْدُ لِلَّهِ رَبِّ ٱلْعَٰلَمِينَ ٢ ٱلرَّحْمَٰنِ ٱلرَّحِيمِ ٣ مَٰلِكِ يَوْمِ ٱلدِّينِ ٤
```

**Результат транслитерации (профиль `Standard`):**

<!-- readme-example:fatiha-output -->
```
бисми-лляяhи-ррохIмаани-ррохIииим 1 аль-хIамду лилляяhи робби-ль-'аалямииин 2 ар-рохIмаани-ррохIииим 3 маалики йауми-ддииин 4
```

Что видно в этом выводе:

* **Длительность мадда показана повтором графемы**: два хараката — графема дважды
  (`лляя`), четыре — трижды (`ииим`), шесть — четырежды. Три длительности
  остаются различимы на письме.
* **Солнечный лям сливается** с последующей буквой (`ррохIмаани`),
  лунный остаётся собой и отделяется дефисом (`аль-хIамду`).
* **Эмфаза окрашивает собственную гласную согласного**: `а` после твёрдого
  согласного пишется как `о` (`робби`), после мягкого ляма — как `я` (`лляя`).
  Гласную перед твёрдым согласным она не трогает.
* **Хамза в начале слова не пишется**: `аль-хIамду`, а не `ъаль-хIамду`.

Эти четыре аята взяты из корпуса (`Transliterator.Core/Resources/Corpus/001.json`),
и тест проверяет, что этот файл показывает ровно то, чего ждёт корпус и что даёт
конвейер.

Ещё несколько прогонов:

<!-- readme-example:runs -->
| Входной текст | Результат |
|---|---|
| `قُلْ هُوَ ٱللَّهُ أَحَدٌ` | `qуль hууа-ллааhу ахIад` |
| `لَمْ يَلِدْ وَلَمْ يُولَدْ` | `лям йалид уалям йууляд` |
| `مِنْ بَعْدِ` | `мим ба'д` |

Последняя строка — икляб: нун сакина перед `ب` переходит в мим, но слова
при этом не сливаются.

## Веб-версия

https://shoralbrt.github.io/Transliterator/

Одна страница на Blazor WebAssembly: ядро скомпилировано в wasm и считает прямо
в браузере. Сервера нет, страница выкладывается на GitHub Pages автоматически
с `master`.

* **Ввод и результат.** Арабский текст набирается справа налево, результат
  пересчитывается на каждую правку. Текст без огласовок тоже принимается, хотя
  без харакатов чтение неполное.
* **Профили.** `Standard` и `Latin` встроены; выбранный профиль запоминается
  между перезагрузками.
* **Готовые суры** из корпуса — в один клик. Текст подставляется по аяту
  на строке, и результат сохраняет строки.
* **Правила профиля** таблицей: варианты стоят под своей буквой, есть поиск
  по ключу.

### Свои профили

* **Создать** профиль можно копией любого существующего и сразу менять графемы
  в таблице правил — результат обновляется по мере ввода.
* **Переименовать и удалить** можно свои профили. Встроенные только копируются
  и не меняются: правка `Standard` сохраняется как `Standard (копия)`.
* Профили хранятся в **localStorage** браузера: переживают перезагрузку и никуда
  не отправляются. Испорченная запись пропускается с сообщением, а не роняет
  страницу.
* **Экспорт и импорт** профиля — JSON в том же формате, что `Standard.json`.
  Так профилем делятся или заносят его в `Transliterator.Core/Resources/Profiles/`.
  Импорт перечисляет всё, что не так с файлом, и не перезаписывает существующий
  профиль: при занятом имени сохраняется копия.

Запустить страницу локально:

```bash
dotnet run --project Transliterator.Web
```

## Использование (CLI)

Первый аргумент — арабский текст, второй (необязательный) — имя профиля;
по умолчанию `Standard`.

<!-- readme-example:cli -->
```bash
dotnet run --project Transliterator.Cli -- "بِسْمِ ٱللَّهِ ٱلرَّحْمَـٰنِ ٱلرَّحِيمِ"
```

Результат, который он выводит:

<!-- readme-example:cli-output -->
```
бисми-лляяhи-ррохIмаани-ррохIииим
```

С явным выбором профиля:

```bash
dotnet run --project Transliterator.Cli -- "بِسْمِ ٱللَّهِ ٱلرَّحْمَـٰنِ ٱلرَّحِيمِ" Latin
```

Запуск без аргументов включает интерактивный режим: приложение предложит ввести
текст вручную или взять пример из «Аль-Фатихи», а затем спросит имя профиля.

## Конвейер

Стадии пронумерованы по порядку исполнения в `RulesService.ApplyTajweedRules`.
Номер — не оформление: каждая стадия опирается на решения предыдущих,
и переставить их местами нельзя.

| # | Стадия | Класс |
|---|--------|-------|
| 1 | Нормализация орфографии | `ArabicNormalizer` |
| 2 | Разбор в поток сегментов | `ArabicParser` |
| 3 | Разметка пауз (вакф) | `WaqfRule` |
| 4 | Хамзат аль-васль | `WaslRule` |
| 5 | Лям артикля | `ArticleRule` |
| 6 | Идгам однородных и близких согласных | `AssimilationRule` |
| 7 | Нун сакина, танвин, мим сакина | `NasalRule` |
| 8 | Тафхим и таркик | `EmphasisRule` |
| 9 | Длительность мадда | `MaddRule` |
| 10 | Кальканя | `QalqalahRule` |
| 11 | Рендеринг по профилю | `CyrillicRenderer` |

Подробный разбор каждой стадии с критериями приёмки — в
[docs/ROADMAP.md](docs/ROADMAP.md).

## Профили

Профиль — JSON-файл в `Transliterator.Core/Resources/Profiles/`. Те же файлы
вшиты в сборку ядра — оттуда их читает браузер.

Сейчас в комплекте два профиля:

* `Standard` — расширенная кириллица;
* `Latin` — латиница с академической диакритикой (`ṯ ǧ ḥ ḫ ḏ š ṣ ḍ ṭ ẓ ġ`, `ʾ` и `ʿ`).

Ни одно правило не знает, для какого письма работает: конвейер один, различаются
только графемы.

### Формат ключа

Ключ — либо сама буква, либо `"буква|вариант"`. Вариант переопределяет базовую
графему в конкретной позиции. Порядок поиска: **вариант → базовый ключ**; базовый
ключ, который нужен тексту, но которого нет в профиле, — ошибка с именем ключа.

| Вариант | Когда применяется | Пример из `Standard` |
|---|---|---|
| `heavy` | под эмфазой (тафхим) | `"َ\|heavy": "о"` — `робби` |
| `soft` | после мягкого ляма | `"َ\|soft": "я"` — `лляя` |
| `sukun` | в закрытом слоге | `"ل\|sukun": "ль"` — `аль-` |
| `waqf` | на паузе | `"ة\|waqf": "h"` |
| `initial` | в начале слова | `"ء\|initial": ""` — хамза не пишется |
| `hiatus` | хамза между гласными | `"ء\|hiatus": "-"` — `уа-иййаака` |
| `ghunna` | при назализации | `"ن\|ghunna": "н"` |
| `qalqalah` | отзвук на размыкании безгласного взрывного | `"ب\|qalqalah": ""` |
| `qalqalah-strong` | он же на паузе; откатывается к `qalqalah` | в `Standard` не задан |

Пустое значение — законная запись, а не пропуск: так в `Standard` осознанно
заданы отзвук кальканя и начальная хамза. Почему именно так — в разделе
«Открытые решения» ROADMAP.

### Чего в профиле нет

Профиль отвечает только за то, **как записать** уже опознанный звук. Что это
за звук, решают стадии 1–10, и до профиля многое просто не доходит:

* **Носители хамзы** (`أ إ ؤ ئ آ ٱ`) — стадия 2 сводит их к одному согласному `ء`
  с его огласовкой. Отдельных ключей для них в профиле нет.
* **Танвин** (`ً ٌ ٍ`) — разворачивается в «краткая гласная + нун сакин»
  и дальше обрабатывается как обычный нун сакина.
* **Надстрочный алиф** (`ٰ`), маддах, татвиль — снимаются нормализацией
  или превращаются в долготу гласной.
* **Долгота** хранится в харакатах (2/4/6) и превращается в повтор графемы
  только на последней стадии; удвоенных гласных в профиле нет.

### Пример профиля

Фрагмент `Transliterator.Core/Resources/Profiles/Standard.json`:

<!-- readme-example:profile -->
```json
{
  "Name": "Standard",
  "Description": "Расширенная кириллица. Ключ вида \"буква|вариант\" переопределяет базовую графему...",
  "Rules": {
    "ء": "ъ",
    "ء|initial": "",
    "ء|hiatus": "-",
    "ب": "б",
    "ب|qalqalah": "",
    "ة": "т",
    "ة|waqf": "h",
    "ح": "хI",
    "ل": "л",
    "ل|sukun": "ль",
    "ن": "н",
    "ن|ghunna": "н",

    "َ": "а",
    "َ|heavy": "о",
    "َ|soft": "я",
    "ُ": "у",
    "ِ": "и",

    "١": "1"
  }
}
```

### Профили из кода

`ITransliterationService` позволяет работать с профилями снаружи конвейера:

```csharp
await service.GetAvailableProfilesAsync();          // имена профилей по алфавиту
await service.GetRulesAsync("Standard");            // правила — копией
await service.UpdateRuleAsync("ر|heavy", "р", "Standard");  // правка одной строки
service.Transliterate(text, profile);               // профиль, которого нет в хранилище
```

`GetRulesAsync` отдаёт именно копию: репозиторий раздаёт профили из кеша,
и правка возвращённого словаря молча меняла бы профиль всем, кто его уже держит.

`Transliterate(text, profile)` принимает профиль, который нигде не сохранён, —
этим путём работает редактор в браузере. Профиль проверяется до расчёта.

## Юнит-тесты

* Тесты на **xUnit**: фонология, все стадии таджвида, профили и их хранилища,
  корпус и сервисы веб-версии.
* Тесты берут настоящие профили из ресурсов, а не копии в коде — прежняя
  хардкодированная копия успела разойтись с оригиналом, и тесты проверяли
  поведение, которого в приложении уже не было.
* Корпус примеров прогоняется целиком: каждый аят в обоих написаниях и каждая
  сура одной строкой. Случаи строятся из файлов корпуса, поэтому добавленная
  сура приносит тесты сама.
* Примеры из этого файла тоже проверяются: фрагмент Аль-Фатихи — по корпусу,
  прогоны и вывод CLI — по конвейеру, выдержка профиля — по `Standard.json`.
* GitHub Actions собирает решение и гоняет тесты на каждый pull request в `master`.

Запуск из командной строки:

```bash
dotnet test
```

В Visual Studio: `Test → Test Explorer`, собрать решение и нажать `Run All`.
